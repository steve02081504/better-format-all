# better-format-all

[English](README.md) · **简体中文** · [日本語](README.ja.md) · [Français](README.fr.md) · [Español](README.es.md) · [हिंदी](README.hi.md)

在资源管理器右键菜单里，用编辑器默认格式化器格式化某个文件夹下所有被 git 跟踪或未提交的文件。

## 功能

- **格式化整个文件夹** —— 在资源管理器中右键任意文件夹，选择 **格式化文件夹内全部文件**。
- **只处理有改动的文件** —— 首次运行会格式化所有被跟踪文件；之后只格式化「自上次完整格式化的 commit 以来发生改动」的文件，以及所有未被 git 忽略的未跟踪文件。未提交的改动总会被纳入。
- **按子路径最小化工作量** —— 每个子路径最后一次完整格式化的 commit 记录在 `.git/better-format-all.json`，因此单独格式化过的子目录在之后格式化其父目录时不会重复处理。
- **使用默认格式化器** —— 通过「格式化文档」执行，因此走已配置的 `editor.defaultFormatter`；扩展不会替你静默选择第一个可用格式化器。
- **可安全取消** —— 进度通知支持取消。取消或部分失败的运行**不会**更新基线，因此下次运行仍会看到所有未格式化的文件。
- **界面本地化** —— 跟随 VS Code 显示语言。

## 用法

1. 在资源管理器中右键 git 仓库内的某个文件夹。
2. 选择 **格式化文件夹内全部文件**。
3. 每个文件会被逐个打开、用其默认格式化器格式化、保存并关闭。

右键不在 git 仓库内的文件夹会报错且不做任何事。

## 基线如何工作

- 状态保存在 `.git/better-format-all.json`（可用 `betterFormatAll.stateFile` 配置），把「相对仓库根的路径」映射到该路径最后一次完整格式化时的 commit SHA；仓库根用空串 `''`。
- 文件以**自身目录或最深层已记录的祖先**为基线。某个路径完整格式化后，它内部更细的条目会被清除——父条目已经覆盖它们。
- 没有基线时，目标下所有被跟踪文件都会被格式化；有基线时，选取 `git diff <sha>` **与工作区**比出的改动文件（因此未提交的修改也算），再加上未跟踪且未被忽略的文件。
- 只有目标完整跑完（未取消、无失败）后才写入基线。

## 设置

| 设置                               | 默认值                   | 说明                                      |
| ---------------------------------- | ------------------------ | ----------------------------------------- |
| `betterFormatAll.stateFile`        | `better-format-all.json` | 写入仓库 `.git` 目录的文件名。            |
| `betterFormatAll.includeUntracked` | `true`                   | 同时格式化未被 git 跟踪且未被忽略的文件。 |

## 要求

- Visual Studio Code 1.100.0 或更高版本。
- `PATH` 上有 `git`。
- 为要格式化的语言配置了默认格式化器（`editor.defaultFormatter`）；语言没有格式化器的文件保持不动。
